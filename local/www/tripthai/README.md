## โหมดสนทนาเสียงสตรีมมิ่ง (ChatGPT-style) ✅ (23 ก.ย. 2026) — ฟรี 100%
ท่อ: **ไมค์ → Whisper small (Docker) → Gemini 2.5 Flash (สมอง) → Piper Thai VITS (ปาก) ทีละประโยค**
- กดไมค์พูด (ตัดจบเองเมื่อเงียบ 4 วิ ไม่ตัดประโยคยาว) → transcript ขึ้น log → Gemini ตอบ (จำบริบท 10 เทิร์น) → เสียงพูดทีละประโยคแบบต่อเนื่อง (โหลดประโยคถัดไปรอไว้ก่อน) + ข้อความค่อย ๆ ขึ้นตามเสียง
- **Barge-in:** กดไมค์ขณะบอทพูด = ขัดจังหวะทันที แล้วพูดต่อได้เลย
- **โหมดพูดต่อเนื่อง** (23 ก.ย. 2026): **ปุ่มไมค์ปุ่มเดียวคุมทั้งหมด** — แตะครั้งเดียวเปิดลูป (ปุ่มเขียว) คุยวนได้เรื่อย ๆ ไม่ต้องกดทีละประโยค แตะอีกครั้งหยุดทั้งหมด (เริ่มอัดไม่สำเร็จลูปดับเองไม่ค้าง)
- ข้อความพิมพ์ยังใช้สมอง rule-based เดิม (เร็ว) — เสียงใช้ Gemini
- ทุกเทิร์นเสียงเข้า ChatDesk ทั้ง 2 ฝั่ง (transcript=customer, คำตอบ=sender bot) + เคารพโหมดคนดูแล
- Infra: `whisper-server/` (whisper + voiceapi Piper + Caddy gateway :8080 ภายใน, ไม่มี tunnel สาธารณะแล้ว), proxy local: `api/stt.php`, `api/tts.php`, `api/gemini.php` (Gemini 2.5 Flash, `maxOutputTokens` 1024 — ภาษาไทยกิน token เยอะ 300 ไม่พอโดนตัดประโยค)
- **จูนเสียงพูด** (23 ก.ย. 2026): Piper พูดช้าลง (rate 0.9) + normalize ข้อความก่อนสังเคราะห์ — คำอังกฤษโรงแรม/สถานที่เป็นคำอ่านไทย (~40 คำ: Patong→ป่าตอง, Centara→เซ็นทารา…), ตัวเลขเป็นคำอ่าน (2,500→สองพันห้าร้อย), เวลา HH:MM เป็นคำอ่าน, เว้นวรรคไทย-อังกฤษช่วยตัวแยกเสียง
- ปุ่ม 🎤 ในช่องพิมพ์: อัดเสียงไม่เกิน 45 วิ → ส่ง `api/stt.php` (PHP proxy บน server นี้) → forward ไป Whisper `small` ใน Docker บนเครื่อง local ผ่าน Cloudflare Tunnel → transcript กลายเป็น bubble `🎤 เสียง (Whisper N วิ)` ใน log + เข้าท่อ ChatDesk เดิม
- ปุ่ม 🔊 บนหัวแชท (default **ปิด** กดฟังเอง): สวิตช์เสียงรวม + ปุ่ม `🔊 ฟังเสียง` ใต้ทุกข้อความบอท (ใช้ speechSynthesis `th-TH` ฟรี)
- Fallback อัตโนมัติ: `Whisper → ไมค์เบราว์เซอร์ (Web Speech th-TH) → แจ้งให้พิมพ์` พร้อมข้อความบอกในแชท ไม่เงียบหาย
- **จูนความเร็ว** (22 ก.ย. 2026): วัดแล้วคอขวดคือ inference (~0.45x realtime) — เปิด `vad_filter` + `initial_prompt` ภาษาไทยท่องเที่ยวที่ฝั่ง server (ตัดเงียบ+ชื่อจังหวัดแม่นขึ้น), ฝั่งวิดเจ็ตตัดจบเองเมื่อเงียบ 4 วิ (WebAudio VAD) + อัดบิตเรตต่ำ (32kbps) + นับวินาทีตอนรอแปลงเสียง
- Chat log รวม: ข้อความพิมพ์/เสียงปนกันเรียงเวลาเหมือนเดิม ข้อความเสียงก็ส่งถึงเจ้าหน้าที่เช่นกัน
- ไฟล์ที่แตะ: `index.html`, `styles.css`, `app.js` + ใหม่ `api/stt.php` | คู่มือ server เสียง: `whisper-server/README.md`

## Bridge วิดเจ็ต ↔ ChatDesk (สองทาง) ✅ (22 ก.ย. 2026)
สาเหตุเดิม: วิดเจ็ตมีแค่บอทท้องถิ่น + iframe หน้าล็อกอิน ข้อความเลยไม่เข้า ChatDesk

**สิ่งที่ทำ:**
- `chatdesk/api/incoming.php` (+1 บรรทัด): รับพารามิเตอร์ `channel=web` → แยกห้องเว็บออกจากห้อง LINE (ของเดิมไม่ส่ง channel = `line` เหมือนเดิม 100%)
- `chatdesk/api/send.php` (+5 บรรทัด): ห้อง `channel=web` ข้ามการพุช LINE (ไม่มี LINE ให้พุช) บันทึกข้อความอย่างเดียว → เจ้าหน้าที่ตอบห้องเว็บได้โดยไม่ error 502
- `chatdesk/api/webthread.php` (ไฟล์ใหม่): endpoint สาธารณะให้แขกอ่านเฉพาะห้อง `WEB_xxx` ของตัวเอง (userId อื่นที่ไม่ขึ้นต้น `WEB_` โดนปฏิเสธ 422)
- `TripThai/app.js` + `index.html`: ทุกข้อความที่พิมพ์ → POST เข้า ChatDesk ทันที (มีชื่อแขก via ปุ่ม 📝 แจ้งชื่อ) + polling ทุก 4 วิ ดึงคำตอบเจ้าหน้าที่มาแสดง + toast แจ้งเตือน
- **คำตอบ AI Bot → ChatDesk ด้วย** (22 ก.ย. 2026): `aiSay()` = แสดงในวิดเจ็ต + ส่งสำเนาเข้า ChatDesk เป็น `sender=bot` (ลอก HTML เหลือข้อความล้วน) ครอบคลุมทุกกิ่ง `aiReply` + ข้อมูลที่พัก + ยืนยันจอง — ข้อความระบบ/error/tักทาย/คำตอบเจ้าหน้าที่ (มีอยู่แล้ว) ไม่ส่งซ้ำ
- **โหมดคนดูแล** (22 ก.ย. 2026): วิดเจ็ตอ่าน `botEnabled` จาก ChatDesk (poll ทุก 4 วิ + เช็คสดก่อน AI ตอบทุกครั้ง) — ถ้าเจ้าหน้าที่ปิดบอท/พิมพ์ตอบเอง (auto-mute) AI ฝั่งเว็บจะหยุดตอบทันที พร้อมข้อความ + สถานะ "เจ้าหน้าที่กำลังดูแล" ส่วนข้อความผู้ใช้ยังส่งถึงเจ้าหน้าที่ปกติ เปิดบอทใหม่ก็กลับมาตอบเอง

**ผลทดสอบ E2E (ผ่านครบลูป):** วิดเจ็ต POST → ขึ้น inbox ChatDesk (conv #7) → admin ตอบผ่าน send.php `ok:true` → แขกอ่านคำตอบผ่าน webthread ได้ → ลบห้องทดสอบแล้ว (inbox เหลือข้อมูลเดิม 3 ห้อง)

**ไฟล์สำรอง:** `incoming.php.bak_tripthai`, `send.php.bak_tripthai` ใน `chatdesk/api/`

## ข้อควรทราบเรื่อง iframe
เซิร์ฟเวอร์ ChatDesk ส่ง header `X-Frame-Options: SAMEORIGIN` → เบราว์เซอร์สมัยใหม่ (Chrome/Edge) จะ**บล็อกการฝัง iframe ข้ามโดเมน** เห็นเป็นหน้าว่าง
→ วิธีใช้จริง: กด **"เปิด ChatDesk เต็มจอ / เปิดในแท็บใหม่"** ในแท็บ ChatDesk (มี fallback ไว้แล้ว) หรือขอให้ admin ปลด header / ทำ widget JS แทน iframe
